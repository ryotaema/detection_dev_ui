# 概要・設計方針

このリポジトリで「何ができるか」「どういう構成か」「機能を足すときに何を守るか」をまとめたものです。
新しく参加する人はまずこれを読んでください。

環境構築の手順は [README.md](../README.md) を参照してください。

---

## 1. 目的

**画像系の学習モデルを作るために必要な作業を、1つの環境で完結させる。**

アノテーション・データ整備・学習・評価・モデル管理までを同じ UI から扱えるようにし、
「必要になる場面がある機能」を余さず1リポジトリで処理できることを目標にしています。

モデルを実際のアプリケーション（ロボット等）に組み込む部分は、このリポジトリの範囲外です。
ここでは **良いモデルを作るところまで** を担当します。

### 想定する使い方

- 画像系に慣れていない人でも、手を動かしながら学べる
- 途中からデータを足したり、別の PC で作ったモデルを持ち込んだりできる
- 作ったデータセット・モデルを他の環境へ持ち出せる

---

## 2. 全体の流れ

```
🏷 Step1: アノテーション  → 🚀 Step3: モデル学習
      ↓                          ↓
📤 Step2: データ取込        🔭 Step4: 推論・評価
```

UI のタブ番号は、画面上部のパイプライン表示と一対一で対応しています。
タブ内の手順は丸数字（①②③）で表記して区別しています。

学習したモデルを CVAT の自動アノテーションにデプロイすると、
Step1 のアノテーション作業そのものが速くなり、この流れが循環します。

初めて使うときは、サイドバー最下部の **「📖 はじめかたガイドを表示」** を有効にすると、
現在の状態と次にやることが画面上部に出ます（データもモデルも無いときは自動で表示されます）。

---

## 3. 実装済みの機能

### アノテーション（Step1）

- CVAT の自動アノテーションモデル（Nuclio 関数）の一覧・デプロイ・再デプロイ・削除
  - モデルのクラス名から `function.yaml` を自動生成するため、ラベル名の不一致が起きない
  - detect は矩形、segment はポリゴンとして CVAT に返す
- **CVAT タスクの新規作成** … 画像をアップロード（または `data/` から選択）して
  タスクを作る。CVAT の画面を開かずにアノテーションを始められる
- ジョブ単位の進捗表示（フレーム数ベースの完了率、担当者別、タスク別、未割当の警告）

### データ取込（Step2）

- CVAT からのエクスポート → YOLO 形式への変換
- 対応タスク種別: `detect` / `segment` / `pose` / `obb` / `classify`
- CVAT を経由しない取込（YOLO 形式 ZIP、画像の直接アップロード）
- チーム共通ラベルのエクスポート（YAML / TXT / CVAT JSON）

### 学習（Step3）

- バックグラウンド学習、エポックごとのリアルタイムグラフ
- MLflow 連携（メトリクス記録・モデルレジストリ登録）
- **学習の停止**（エポック末で安全に打ち切り）
- **中断した学習の再開**（`last.pt` から続きから）
- 既存モデルを初期重みにした追加学習
- プリセット管理、データ拡張・最適化パラメータの調整
- **ハイパーパラメータ探索** … 設定を少しずつ変えながら学習を繰り返し、
  精度の良い組み合わせを探します（`model.tune()`）
  - **始める前に所要時間を見積もります**（1 回ごとに学習をまるごと回すため）
  - 目的別に「学習率まわり / 損失の重み / データ拡張 / すべて / 自分で選ぶ」から選べます
  - **振る項目は絞るほど良い設定に届きます**（1 回ごとに学習をまるごと回すため）。
    増やしすぎると注意が出ます
  - 探索は ③ 詳細設定と同じ条件（optimizer / imgsz / batch）で回すので、
    見つけた設定はそのまま本番の学習で再現します
  - **探し方を選べます**。回数が少ないうちは遺伝的アルゴリズム、
    15 回以上なら TPE が有利です（回数に応じて推奨を出します）
  - **いつも同じ値で回したい項目は固定できます**。探索から外れるぶん、
    残りの項目を試す回数が増えます
  - 途中で止められます（いま回している学習が終わり次第）
  - **探索中は、いま何回目・どの設定を試しているか（既定からの振れ幅つき）・
    何エポックまで進んだか・各回の成績が見えます**（1 回に時間がかかるため）
  - 結果はそのまま学習プリセットとして保存でき、① から呼び出せます
- **データ拡張のプレビュー** … 設定した拡張が画像に何をするかを学習前に確認できる
  （パラメータの意味を掴むための近似表示）

### 学習（Step3）

`① プリセット → ② モデルとデータセット → ③ 詳細（任意）→ ④ 確認して開始` の順に並びます。
進捗バー・リアルタイムグラフ・ログは**設定より前**にあり、学習中はそこが主役になります。

### 推論・評価（Step4）

このタブは内部で 3 つに分かれています。推論が主役で、
精度測定と深掘り分析は「推論したあとに使うもの」なので後ろに置いています。

| 内部タブ | 中身 |
|---|---|
| ▶ ① 推論する | ①推論する対象を選ぶ → ②推論を実行する → ③結果を確認する → ④書き出す |
| 📊 ② 精度を測る | モデル評価・mAP の比較表・クラス別 AP・混同行列 |
| 🔬 ③ 深掘り分析 | 要確認画像の抽出 → CVAT へ書き戻し、conf 探索、正解ラベルとの差分分析 |

- 画像 / ディレクトリ / 動画の推論（トラッキング、テンポラル平滑化つき）
- **過去の学習の比較（MLflow）** … run を並べて設定と精度の対応を見る。
  学習曲線を重ねて表示できる。MLflow が落ちていても `results.csv` から比較できる
- **モデル評価** … 任意のデータセットで `model.val()` を実行し、mAP・クラス別 AP・
  推論速度を測定。モデル横断の比較表を作る
  - detect / segment / obb は mAP、classify は top1 / top5
- **正解ラベルとの差分分析** … 画像ごとの TP/FP/FN を算出し、
  アノテーション漏れの候補を抽出
- **最適な conf の探索** … しきい値を振って Precision / Recall / F1 を測り、
  「バランス重視」「誤検出を避ける」「見逃しを避ける」の目安を出す
- **プレビューの拡大確認** … 一覧では 1 枚が画面の 1/3 程度で判断できないため、
  選んだ 1 枚を大きく表示する。「画像全体」と「検出ごとに拡大」を切り替えられ、
  閉じずに前後の画像へ移動しながらフラグを付けられる
  （1 枚ずつ開き直すと 100 枚の確認が現実的でないため）
- **精査の記録** … 🚩 を付けた記録は `data/<dataset>/.review_state.json` に残ります。
  **ブラウザを再読み込みしても消えません**（5000 枚を見る作業では致命的なため）。
  データセットと一緒に移動・持ち出しできます
- **要確認画像の自動抽出** … 検出ゼロ・低信頼度・クラス競合・極小ボックス
- **CVAT への書き戻し** … 抽出した画像を予測ボックス付きで新規タスクとして作成
- FiftyOne による可視化（正解と予測を重ねた比較ビューを含む）

### オプション機能

全員が必要とするわけではない機能は、サイドバーの **「🧰 使う機能」** で
出し入れできます。**既定はすべてオフ**なので、素の状態から始まります。

| 機能 | どこに出るか |
|---|---|
| 🟦 モザイク | 「📁 データ管理」のデータセット操作に追加されます |
| ✂️ クロップ生成 | 専用のタブが増えます |

クロップ生成では、**どの検出モデル・どの重み（sha1）で作ったか**をクロップごとの
メタ (`meta/*.json` の `bbox_model`) に記録します。モデルを更新しても重みのパスは
変わらないため、ハッシュが無いと「どの時点のモデル由来か」を追えません。
「🔎 確認用の重ね描きも出す」を入れると `debug/` に数枚だけ確認画像が出ます
（緑=検出した対象 / 青=学習で使う内側の範囲 / 灰=写り込んだ他の対象）。

対象が写っていない画像は**背景タイル**に分割できます。枚数は「背景がデータセットに
占める割合」で指定します（既定 15%）。対象クロップの枚数は撮り足すたびに変わるため、
枚数ではなく割合で持ちます。採らなかったタイルは消さず `background/_unused/` に
残るので、あとから足せます。空タイルの自動除去はしません（採否は人が決めます）。
抽選の方法（ランダム / 元画像ごとに均等 / 全部）と種は選べます。
作ったあとは「⑤ 背景タイルを選別する」から、タイルを見ながら採否を直せます
（外しても消えず `_unused/` に移るだけなので、何度でもやり直せます）。

設定は保存されるので、一度オンにすれば次回から出たままです。

### 拡張機能

`extensions/` に別リポジトリを `git clone` すると、その道具専用のタブが増えます。
本体を大きくせずに機能を足していくための仕組みです。

```bash
cd extensions
git clone https://github.com/ryotaema/anno_dataset_tools
# ブラウザを再読み込みするとタブが増えます
```

- 取り込み方は 3 通り … `streamlit`（タブ内に直接描画）/ `command`（CLI 実行）/
  `desktop`（ホストで実行する手順を提示）
- **Tkinter などのデスクトップ GUI はブラウザに出せません**。
  この UI はコンテナ内で動いていて画面を持たないためです。
  `data/` はホストと同じ実体なので、ホストで動かしても同じファイルを扱えます
- 書き方は `extensions/README.md` にあります

### フォルダを開く

データセット・モデル・推論結果・クロップの出力先・拡張のカードから、
**OS のファイルアプリでそのフォルダを開けます**。

この UI は Docker コンテナの中で動いていて画面（X ディスプレイ）を持たないため、
自分でファイルアプリを起動することはできません。そこで 2 段構えにしています。

| | 何が起きるか | 準備 |
|---|---|---|
| 常に | ホスト側のパスを表示する。コピーすればどこでも使える | 不要 |
| 任意 | ボタン 1 つでファイルアプリが開く | 下記の常駐を動かしておく |

いまどちらの状態かは、**サイドバー**に出ます（`📂 フォルダを開く: ✅ 使えます`）。

#### ワンクリックで開けるようにする

ホスト側で一度だけ実行すれば、以降はログインのたびに自動で動きます。

```bash
./tools/install_folder_watcher.sh            # 登録して開始
./tools/install_folder_watcher.sh --status   # 状態を見る
./tools/install_folder_watcher.sh --uninstall # 解除
```

systemd のユーザーサービスとして登録します（`systemd --user` が無い環境では、
デスクトップの「自動起動するアプリ」に `tools/open_folder_watcher.sh` を
登録してください）。その場だけ動かすなら直接実行するだけでも構いません。

```bash
./tools/open_folder_watcher.sh
```

ホスト側のパスは `docker inspect` でマウント表を引いて求めます
（決め打ちにすると、別の場所に clone した人の環境で外れるため）。

### データ管理

- データセット / モデルの一覧・削除。どちらも `st.container(border=True)` のカード。
  データセットの操作（再分割・クラス編集・持ち出し・品質チェック・画像追加）は
  カード内のラジオで 1 つだけ開く（expander を並べると件数分だけ縦に伸びるため）
- **train/val の再分割** … 比率とシードを指定して混ぜ直す
  （classify はクラスごとに比率を保つ層化分割。シンボリックリンクも保持）
- **クラス名の編集・統合・削除** … ラベルのクラスID を振り直し、data.yaml も更新
- **品質チェック** … 画像とラベルの対応漏れ、座標の破損、クラス分布の偏り
- **重複画像の検出** … 中身のハッシュで照合する（名前が違っても中身が同じなら重複）。
  **同じ画像が train と val の両方に入ると評価が実力より高く出る**ため、
  統合の前に調べられるようにしている
- **壊れたラベルの自動修正** … `.txt.bak` にバックアップしてから除去
- **モデルの並べ替え・絞り込み** … おすすめ順（お気に入り→精度→新しさ）/
  新しい順 / よく使う順 / 最後に使った順 / 精度順 / 名前順。
  状態・お気に入り・評価済み・未使用で絞り込める
- **使い忘れの防止** … 作ったのにまだ使っていないモデルを別枠で知らせる。
  「学習したのに適用し忘れた」を防ぐためのもので、一度使えば表示されなくなる
- **外部モデルの取込** … `.pt` をアップロードし、読み込み検証とクラス名の記録
- **持ち出し** … データセット ZIP（画像込み / ラベルのみ）、
  モデル `.pt` 単体、学習ログ込みの一式 ZIP
- **モザイク（写り込みを隠す）** … 背景データに入ってしまった対象物や、
  顔などを隠す。隠す場所は「モデルの検出結果」「顔の自動検出」「固定領域」
  「CVAT の `mask` ラベル」から選べる
  - **顔のモザイクは重ねてかけられる**（設定でオン/オフ）。
    対象物と顔を 1 回の操作で同時に隠せる
  - **顔検出は OpenCV だけで完結**（YuNet / MIT）。ボタン1つでモデルを取得できる。
    ネットワークに出られない環境では OpenCV 同梱の Haar も選べる
  - **アノテーション済みの物体と重なると警告を出し、確認するまで適用できない**
    （隠すとその学習データが壊れるため）
  - 適用したあとも、処理前後を並べて隠し漏れが無いか見直せる
  - 元画像を上書きするが、`_backup_original/` へ退避してからなので元に戻せる
  - 隠し漏れのほうが高くつくので、しきい値は低め・余白ありが既定
- **精査の進み具合** … カードに「👀 精査 320 / 5741 枚（6%）🚩 要修正 12 枚」と出ます。
  すべて確認し終えると、状態を 🟢 精査済み にするよう促します
- **状態とタグ** … データセット / モデルに「いまどの段階か」（排他の 1 つ）と
  「どういう性格か」（自由・複数）を付けられる。一覧は状態・タグで絞り込める
  - データセット: 🟡作成中 / 🟠自動アノテのみ / 🟢精査済み / 🔵テスト用 / ⚪保管
  - モデル: 🧪実験中 / 🔬候補 / 🚀実用 / 🗑非推奨
  - Step3 は `test_only` を選ぶと警告し、Step4 の評価では逆に `test_only` を勧める
- **データセットの統合** … クラス ID を統合先の並びに振り直してから混ぜる
  （`names` の順序が違うデータセットをそのまま混ぜるとラベルが別クラスに化けるため）。
  何と何を混ぜたかを来歴に残す
- **片付け（🧹）** … 学習に使えないデータセット・重みの残っていない学習・
  作り直せる一時ファイル・重複しているデータセットをまとめて見つける。
  **自動では何も消さず**、消す前に「そのデータで学習したモデル」を確認できる
- **使用実績の逆引き** … そのデータセットで学習したモデルを来歴から辿って表示する。
  「消してよいか」の判断材料になる。実用中のモデルが使っている場合は
  削除前に確認を求める
- **来歴の追跡** … `CVAT タスク → データセット → モデル` の連鎖を辿れる。
  統合データセットは親が複数あるので木構造で表示する。
  学習時点の枚数を記録するので、あとでデータを足しても当時の条件が分かる

### 共通

- **エラーの原因と対処の提示** … GPU メモリ不足・接続断・クラス数不一致など
  よくある失敗を見分けて、次にやることを添えて表示する（`core/errors.py`）

## 4. コード構成

```
app/
├── main.py    エントリ（設定・テーマ・ヘッダー・サイドバー・はじめかたガイド・タブ呼び出し）
├── core/      画面を持たないロジック層
│   ├── config.py       パス・URL・共通定数（他のどのモジュールにも依存しない）
│   ├── state.py        バックグラウンド処理の共有状態
│   ├── utils.py        IoU 計算・スラッグ化など広く使う小物
│   ├── provenance.py   来歴管理
│   ├── cvat.py         CVAT の取得・エクスポート・書き戻し
│   ├── dataset.py      データセット生成・品質チェック・修正・再分割・クラス編集・ZIP
│   ├── models.py       モデルのメタ情報・持ち出し
│   ├── training.py     学習ワーカー
│   ├── evaluation.py   評価・正解ラベルとの差分分析・conf 探索
│   ├── inference.py    推論・描画・書き出し
│   ├── serverless.py   Nuclio 連携
│   ├── experiments.py  MLflow の実験比較
│   ├── errors.py       エラーの解釈と対処の提示
│   ├── augment_preview.py データ拡張のプレビュー生成
│   └── fiftyone_app.py FiftyOne
├── ui/        画面
│   ├── widgets.py      説明つきスライダーなど共通部品・エラー表示
│   ├── presets.py      学習パラメータのプリセット
│   └── tab_*.py        各タブ（render_xxx() として独立）
└── tests/     pytest（core/ のロジックが対象）
```

`core/` は Streamlit のウィジェットを呼びません。ロジックだけを置き、
UI から `from core import *` で使います。

各タブは `ui/tab_*.py` に `render_xxx()` として独立していて、
`main.py` は `with tab0: render_annotate()` のように呼ぶだけです。
タブを1つ触るときに他のタブを読まなくて済むようにするためです。

依存の向きは `config → state → utils → provenance → dataset → その他` の一方向で、
循環参照を作らないでください。

`from core import *` はアンダースコア始まりの名前を取り込まないため、
`core/__init__.py` で明示的に再エクスポートしています。
core に `_foo` を追加したら `__init__.py` にも追記してください。

新しい処理を書くときは、**まず core 側に関数として書き、
main.py からはそれを呼ぶだけ**にすると、テストしやすく読みやすくなります。

## 5. 設計の方針

機能を足すときは、次の4点を守ってください。

### どの段階からでもデータを入れられるようにする

CVAT 経由だけを前提にしないでください。ZIP、画像単体、他の PC で作った `.pt` など、
**途中から合流できる経路**を必ず用意します。既存の取込機能はすべてこの方針に沿っています。

### 入れたものは出せるようにする

取り込めるが持ち出せない、という状態を作らないでください。
データセットもモデルも ZIP で書き出せます。新しい成果物を追加したら、
出口も同時に用意します。

### 判断材料を UI の中に出す

「どのモデルを使うべきか」「このデータで学習してよいか」を、
外部ツールを開かずに判断できるようにします。
同一条件での mAP 比較、推論速度、正解ラベルとの差分がこれにあたります。

### 壊れたデータは検出して直せるようにする

外部から持ち込んだデータや複数人で作ったデータは必ず壊れます。
検出（品質チェック）と修正（自動修正）をセットで用意し、
**修正前にバックアップを取る**のを原則とします。

## 6. 実装上の注意点

作業中に踏んだ落とし穴を残しておきます。同じところで詰まらないように。

### Ultralytics

- **学習の停止に `trainer.stop = True` を使わない**
  「予定エポックを完走した」と記録され、`resume` できなくなります。
  例外でループを抜け、エポック末の `last.pt` を残す方式にしています。
- **`resume=True`（bool）を渡さない**
  Ultralytics が「最新の run」を自動探索し、無関係な学習を再開します。
  必ず `last.pt` のパスを渡してください。
- **画像リストを `predict()` に渡すと `Results.path` が仮名になる**
  （`image0.jpg` など）。入力順が保たれることを利用して元パスと対応付けます。
- **`classify` は `data.yaml` ではなくディレクトリを渡す**
  データセット構造も `<split>/<クラス名>/*.jpg` と他タスクで異なります。
  `resolve_train_data_arg()` がこの差を吸収します。
- **指標の入り場所がタスクで違う**
  detect は `r.box`、segment は `r.seg`、obb は `r.obb`、classify は `r.top1` / `r.top5`。

### Streamlit

- **`st.expander` は入れ子にできない**（例外になります）。
  中で開閉したい場合は `st.checkbox` + `st.container(border=True)` を使ってください。
- **タブの描画途中で `st.rerun()` を呼ばない**
  スクリプトがそこで打ち切られ、**それ以降のタブが描画されません**
  （データ管理やトピックスが真っ白になる、他の入力が操作できなくなる）。
  進捗を追うための定期実行は `request_rerun_poll()` で予約し、
  すべて描き終えた `main.py` の末尾で `consume_rerun_poll()` がまとめて実行します。
- **条件によってトップレベルの要素を増減させない**
  Streamlit は要素を「上から何番目か」で識別します。`st.tabs` の前にある要素が
  条件分岐で出たり消えたりすると、タブの識別がずれて画面が真っ白になります。
  出し入れしたいものは `st.container()` を常に置き、**その中身だけ**を切り替えてください
  （はじめかたガイドがこの形です）。
- **タブの直前・直後で `st.tabs` を二重に置かない**
  入れ子のタブ自体は問題ありませんが、トップレベル付近で並ぶと表示が壊れることがあります。
  ラジオでの切り替えに置き換えるのが安全です。
- **開きタグと閉じタグを別々の `st.markdown()` に分けても要素を囲めない**
  `st.markdown()` は呼び出しごとに独立した DOM ブロックになるため、
  `st.markdown('<div class="card">')` … `st.markdown('</div>')` と書いても
  カードにはならず、**中身が空の枠だけ**が描画されます
  （閉じタグ側は宙に浮いて無視されます）。
  枠で囲みたいときは `st.container(border=True)` を使ってください。
  自前の HTML は 1 回の呼び出しで完結させます
  （セクション見出しの `.section-head` はこの形にしています）。
- **横並びのラジオ（`horizontal=True`）は折り返さない**
  選択肢が増えると 1 行に収まらなくなり、**端の選択肢が押し出されて
  クリックできなくなります**（スクロールもしません）。
  `[data-testid="stRadio"] > div[role="radiogroup"]` に `flex-wrap: wrap` を
  当てて折り返させています。選択肢を増やすときはラベルも短く保ってください。
- **タブが増えると横にあふれる**
  タブは 6 固定 + オプション機能 + 拡張の数だけ増えます。
  タブ一覧は横スクロールさせています（折り返すと選択中の下線がずれるため）。
- **`st.columns()` は画面幅が狭くても等分のまま**
  折り返しません。ラベルの長い指標を 5 列に並べると狭い画面で潰れます。
  表示するだけの指標は `metric_row()`（`ui/widgets.py`）を使ってください。
  flex-wrap の HTML なので幅に応じて段が増えます。
  入力を含むカラムは 900px 未満で縦に積むよう CSS で手当てしていますが、
  これは Streamlit の DOM 構造に依存するので、
  バージョンを上げたときは効いているか確認してください。
- **実行中だからといって設定ウィジェットを描画から外さない**
  Streamlit はその run で描画されなかったウィジェットの状態を破棄します。
  学習中に設定を隠すと、終わったときに入力値が既定値へ戻ってしまいます。
  隠したいときは描画したまま順序を変える（Step3 は進捗を設定より前に出しています）か、
  `expander` に入れてください（`expander` の中身は畳んでいても描画されます）。
- **`components.html()` の中は親の CSS 変数を継承しない**
  iframe として描画されるため、`var(--accent)` などは効きません。
  `ui/theme.py` の `active_theme()` から実際の色を取り出して埋め込んでください
  （学習ログのビューアがこの形です）。
- バージョンは 1.35.0 固定です。`st.image()` は `use_column_width` を使います
  （`use_container_width` は未対応）。
- バックグラウンド処理の状態は `@st.cache_resource` で共有し、
  `st.session_state` はスレッドから触らないでください。

### 推論結果の保存

`predictions/*.json` のファイル名は `<画像名>__<パスのハッシュ8桁>.json` です。
画像名だけで付けると、別のデータセットにある同名画像（`1000color.png` のような
連番名は特に）で前の結果を黙って上書きしてしまうためです。
同じ画像を再推論した場合は同じ名前になるので、意図した上書きは従来どおり効きます。
一覧に出す名前は `prediction_display_name()` で元画像名に戻します。

### テスト

`app/tests/` に pytest のテストがあります（約30秒で完走）。

- `test_*.py` … `core/` のロジック（画面・GPU・外部サービスに依存しない）
- `test_ui_smoke.py` … **UI の通し検査**。全タブが描画されるか、
  チェックボックスやボタンを操作しても壊れないかを見ます。
  「例外は出ないのに画面が壊れる」不具合はこれで拾います

```bash
docker compose exec -w /app streamlit_app python -m pytest tests/ -q
```

機能を追加したらテストも足してください。特に
**データを壊しうる処理**（ラベルの修正、再分割、クラス編集）は必ず書きます。
テストが本当に効いているかは、わざとロジックを壊して落ちることを確認すると分かります。

**ボタンには必ず `key` を付けてください。** UI 検査は key を見て
「押すと重い処理が走るボタン」を除外します。key が無いと除外できず、
検査中に学習や推論が実際に走ってしまいます
（実際に 5,700 件の推論が走ったことがあります）。
重い処理を伴うボタンを追加したら `test_ui_smoke.py` の
`HEAVY_KEYS` / `HEAVY_PREFIXES` にも登録します。

### 動作確認（UI）

UI の変更は `streamlit.testing.v1.AppTest` で例外を検出できます。

```python
from streamlit.testing.v1 import AppTest
at = AppTest.from_file('/app/main.py', default_timeout=600)
at.run()
print(len(at.exception), len(at.error))
```

ボタンやウィジェットは `key` で取得して操作できます。

```python
[b for b in at.button if b.key == 'ev_run'][0].click().run()
```

新しい機能を足したら、少なくとも「例外0件」は確認してください。
